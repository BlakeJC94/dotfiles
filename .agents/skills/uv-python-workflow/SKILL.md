# Python development with uv

## When to Use

Use this workflow for Python project setup, dependency management, execution, formatting, linting, and type checking. Follow repository-specific instructions when they add compatible checks or configuration.

## Procedure

1. **Inspect the project** - Read `pyproject.toml`, `uv.lock`, and local agent instructions before choosing commands. Do not replace an existing project workflow without approval.
2. **Initialize projects** - Every Python project uses `pyproject.toml`; create new projects with `uv init`. Default new projects to `requires-python = ">=3.12"` unless specified otherwise. Keep uv's default hatchling build system unless asked to change it.
3. **Manage dependencies** - Use `uv add <package>` for runtime dependencies and `uv add --dev <package>` for development dependencies. Use corresponding `uv remove` commands to remove them. Never hand-edit dependency declarations or `uv.lock`.
4. **Install and run** - Use `uv sync` (or `uv sync --dev`) to install dependencies. Run project commands as `uv run <command>`; do not manually activate a virtual environment.
5. **Configure project tools** - Keep Ruff and ty configuration in `pyproject.toml`, not `ruff.toml` or `.ruff.toml`. Installable CLI/GUI projects declare entry points under `[project.scripts]` and/or `[project.gui-scripts]`.
6. **Verify Python changes** - Run the required checks through uv:
   - `uv run ruff format --check`
   - `uv run ruff check`
   - `uv run ty check`

## Pitfalls

- Do not use `pip`, `venv`, `virtualenv`, `pip-tools`, Poetry, PDM, or conda.
- Do not hand-maintain `requirements.txt`, dependency tables, or `uv.lock`.
- Do not use Black or isort for formatting, Flake8 or Pylint for linting, or mypy or pyright for typing. Use Ruff and ty instead.
- Use `uv run python script.py` rather than invoking project Python scripts directly; prefer a declared entry point for installable commands.
- Do not use `[tool.setuptools.scripts]`, a top-level `scripts` table, or `console_scripts` under `[tool.setuptools]`.
- If a project already configures Pyrefly, use its existing check in addition to the default checks; do not introduce it as a replacement for ty without approval.

## Verification

- Dependency changes were made with `uv add` or `uv remove`, and `uv.lock` remains generated by uv.
- Python commands were run with `uv run`.
- After Python changes, `uv run ruff format --check`, `uv run ruff check`, and `uv run ty check` pass.
